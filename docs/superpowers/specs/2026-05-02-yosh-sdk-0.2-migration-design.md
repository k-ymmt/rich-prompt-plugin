# yosh-plugin-sdk 0.2 への追従マイグレーション設計

**Date:** 2026-05-02
**Target version:** rich-prompt-plugin 0.2.0
**Source version:** rich-prompt-plugin 0.1.2

## 背景

`rich-prompt-plugin` は yosh シェル用のプロンプトプラグイン。現状（v0.1.2）は古い yosh-plugin-sdk（git revision `a927f67`）に依存し、ネイティブ dynamic library (`.dylib` / `.so`) としてビルドされている。

最新の yosh-plugin-sdk **0.2.x** で配布形式・FFI モデルが破壊的に変わった。プラグインは WebAssembly Component (`.wasm`) として配布され、ホストとのやり取りは WIT (`yosh:plugin@0.2.x`) インターフェース経由になる。本ドキュメントは追従マイグレーションの設計をまとめる。

## SDK の主な破壊的変更

| 項目 | 旧 (v0.1.x SDK) | 新 (v0.2.x SDK) |
|---|---|---|
| 配布形式 | ネイティブ dylib / so | WebAssembly Component (`.wasm`) |
| ビルド | `cargo build` | `cargo component build --target wasm32-wasip2` |
| ビルドツール | rustc 単独 | `cargo-component`、`wkg`、`wasm32-wasip2` ツールチェイン |
| `Plugin::commands` | `&[&str]` | `&[&'static str]` |
| `Plugin::exec` | `(&mut self, &PluginApi, &str, &[&str])` | `(&mut self, &str, &[String])` |
| Hooks | `(&mut self, &PluginApi, ...)` | `(&mut self, ...)` （`PluginApi` 引数除去） |
| `implemented_hooks` | （存在せず） | **必須**: 実装するフックを enum で明示 |
| ホスト関数 | `api.cwd() -> String` 等のメソッド | `yosh_plugin_sdk::cwd() -> Result<String, ErrorCode>` 等の自由関数 |
| 戻り値 | 失敗を握りつぶす | 全て `Result<_, ErrorCode>` |
| `panic` 設定 | 任意 | `panic = "abort"` 必須（`wasi:cli/stderr` 引き込み回避） |

## 機能スコープ

機能は **完全維持** する。表示は v0.1.2 と同等。

```
kazuki@mac ~/Projects/rust  main [+2 !1 ?3] took 3s
❯
```

- ユーザー名 + ホスト名（短縮）
- カレントディレクトリ（HOME を `~` 置換）
- git ブランチ + staged / unstaged / untracked カウント
- コマンド実行時間（≥ 2s 表示）
- プロンプト文字（成功=緑、失敗=赤）

## WASM 環境の制約と影響

yosh のプラグインランタイムは wasmtime 上で動作し、`yosh:plugin/*` のホストインポートのみ提供する。WASI Preview 2 のシンボルはリンカに登録されているが `WasiCtx` は完全に空（preopens なし、stdio なし、env なし）。これは `kish/src/plugin/linker.rs:57-74` および `kish/src/plugin/host.rs:60` で確認済み。

その結果、現状の依存クレートが使えなくなる:

- **`git2 = "0.20"`** (libgit2 C ライブラリ) — wasm32-wasip2 でビルド不能
- **`whoami = "1"`** — OS API 依存、wasm では機能しない
- **`gethostname = "1"`** — 同上

さらに `gix` のような pure-Rust git ライブラリも、`std::fs` 経由でファイルを開く実装になっているため、preopens 空の `WasiCtx` 下では実行時にファイルを開けない。**プラグインは `yosh_plugin_sdk::read_file()` 経由（= `yosh:plugin/files` ホストインポート）でしかファイルアクセスできない**。

## 機能再実装方針

### git 情報（ハイブリッド戦略）

| 取得対象 | 手段 | 失敗時の挙動 |
|---|---|---|
| リポジトリ判定 + ブランチ名 | `read_file(.git/HEAD)` を `cwd` から親方向へ walk して見つける。テキストフォーマットを自前パース | リポ未検出 → git segment 全体を非表示 |
| staged / unstaged / untracked カウント | `commands:exec` で `git status --porcelain=v1 --untracked-files=all` を 1 回実行、結果をパース | 失敗（denied / not found / 異常終了）→ カウント全て 0 として扱い、ブランチ名のみ表示 |

**判断根拠**:

- リポジトリ外（多数派ケース）では外部プロセス起動を一切行わない。プロンプト表示の常時コストを最小化。
- ブランチ名は `.git/HEAD` を読むだけで取れる（`ref: refs/heads/<name>\n` か bare 40-hex hash の単純フォーマット）。`gix` のような重量依存は不要。
- staged/unstaged/untracked のカウントを自前で行うには `.git/index` のバイナリパースとワーキングツリーとの diff が必要で、実装コストが過大。`git status --porcelain` を 1 回叩くほうが堅牢かつ実装が短い。

### user / host

`on_load` で `commands:exec` 経由で `whoami` と `hostname` を一度だけ実行し、結果をプラグイン内にキャッシュ。以降のプロンプトでは在庫値を使う。

- 起動時 1 回のみのコスト。プロンプト毎のコストはゼロ。
- `commands:exec` が拒否された / コマンドが PATH にない場合は `"user"` / `"host"` をフォールバック値として使用（プラグイン全体は機能継続）。

### 時刻計測

`Instant::now()` は yosh が WASI Preview 2 を完全リンクしており、デフォルトの `WasiCtxBuilder::new().build()` で clocks が有効なため動作する見込み。実装中に動かなければ `commands:exec date +%s%N` でフォールバック検討（リスクメモ）。

## `Plugin` trait 実装の骨子

```rust
use std::time::{Duration, Instant};
use yosh_plugin_sdk::{
    Capability, HookName, Plugin, export,
    cwd, exec, get_var, print, set_var,
};

mod segments;

#[derive(Default)]
struct RichPromptPlugin {
    last_exit_code: i32,
    last_cmd_start: Option<Instant>,
    last_duration: Option<Duration>,
    user: String,
    host: String,
}

impl Plugin for RichPromptPlugin {
    fn commands(&self) -> &[&'static str] { &[] }

    fn required_capabilities(&self) -> &[Capability] {
        &[
            Capability::Io,
            Capability::Filesystem,
            Capability::VariablesRead,
            Capability::VariablesWrite,
            Capability::FilesRead,
            Capability::CommandsExec,
            Capability::HookPreExec,
            Capability::HookPostExec,
            Capability::HookPrePrompt,
        ]
    }

    fn implemented_hooks(&self) -> &[HookName] {
        &[HookName::PreExec, HookName::PostExec, HookName::PrePrompt]
    }

    fn on_load(&mut self) -> Result<(), String> {
        self.user = exec("whoami", &[])
            .ok()
            .and_then(|o| String::from_utf8(o.stdout).ok())
            .map(|s| s.trim().to_string())
            .unwrap_or_else(|| "user".to_string());
        // `hostname` の出力（FQDN になり得る）を最初の `.` までで切り詰めて
        // キャッシュ。username::truncate_hostname を使う。
        self.host = exec("hostname", &[])
            .ok()
            .and_then(|o| String::from_utf8(o.stdout).ok())
            .map(|s| segments::username::truncate_hostname(s.trim()).to_string())
            .unwrap_or_else(|| "host".to_string());
        Ok(())
    }

    fn exec(&mut self, _cmd: &str, _args: &[String]) -> i32 { 0 }

    fn hook_pre_exec(&mut self, _cmd: &str) {
        self.last_cmd_start = Some(Instant::now());
    }

    fn hook_post_exec(&mut self, _cmd: &str, exit_code: i32) {
        self.last_exit_code = exit_code;
        self.last_duration = self.last_cmd_start.take().map(|s| s.elapsed());
    }

    fn hook_pre_prompt(&mut self) {
        let cwd_str = cwd().unwrap_or_default();
        let home = get_var("HOME").ok().flatten();

        let mut parts: Vec<String> = Vec::new();
        parts.push(segments::username::render(&self.user, &self.host));
        parts.push(segments::directory::render(&cwd_str, home.as_deref()));
        if let Some(g) = segments::git::render(&cwd_str) {
            parts.push(g);
        }
        if let Some(d) = self.last_duration
            && let Some(seg) = segments::duration::render(d)
        {
            parts.push(seg);
        }

        let line1 = parts.join(" ");
        let line2 = segments::character::render(self.last_exit_code);
        let _ = print(&format!("{line1}\n"));
        let _ = set_var("PS1", &format!("{line2} "));
    }
}

export!(RichPromptPlugin);
```

**注意点**:

- `cwd()` 失敗時は空文字列にフォールバック（既存挙動と等価）。
- `on_load` 失敗時も `Err(_)` を返さず継続（`commands:exec` 拒否環境でもプラグインロードは成功させる）。
- `username::render` は引数 `(user: &str, host: &str)` を取る形に変更。`whoami::username()` 直接呼び出しは消える。

## `segments::git` の新設計

```rust
use yosh_plugin_sdk::{exec, read_file};
use yosh_plugin_sdk::style::{Color, Style};

pub fn render(cwd: &str) -> Option<String> {
    let head_content = find_head(cwd)?;
    let branch = parse_branch(&head_content);
    let (staged, unstaged, untracked) = status_counts().unwrap_or((0, 0, 0));

    let mut result = Style::new()
        .fg(Color::Magenta).bold()
        .paint(&format!("\u{e0a0} {branch}"));
    let parts = build_status_parts(staged, unstaged, untracked);
    if !parts.is_empty() {
        result.push_str(&format!(" [{}]", parts.join(" ")));
    }
    Some(result)
}

fn find_head(cwd: &str) -> Option<String> {
    let mut dir = cwd.trim_end_matches('/').to_string();
    loop {
        let path = if dir.is_empty() {
            "/.git/HEAD".to_string()
        } else {
            format!("{dir}/.git/HEAD")
        };
        if let Ok(bytes) = read_file(&path)
            && let Ok(s) = String::from_utf8(bytes)
        {
            return Some(s);
        }
        match dir.rfind('/') {
            None => return None,
            Some(0) if dir.is_empty() => return None,
            Some(0) => dir.clear(),
            Some(i) => dir.truncate(i),
        }
    }
}

fn parse_branch(head: &str) -> String {
    let trimmed = head.trim();
    if let Some(refpath) = trimmed.strip_prefix("ref: ") {
        return refpath.rsplit('/').next().unwrap_or(refpath).to_string();
    }
    trimmed.chars().take(7).collect::<String>()
}

fn status_counts() -> Option<(usize, usize, usize)> {
    let out = exec(
        "git",
        &["status", "--porcelain=v1", "--untracked-files=all"],
    ).ok()?;
    if out.exit_code != 0 { return None; }
    Some(parse_status_porcelain(&String::from_utf8_lossy(&out.stdout)))
}

fn parse_status_porcelain(stdout: &str) -> (usize, usize, usize) {
    let mut staged = 0usize;
    let mut unstaged = 0usize;
    let mut untracked = 0usize;
    for line in stdout.lines() {
        let mut chars = line.chars();
        let x = chars.next().unwrap_or(' ');
        let y = chars.next().unwrap_or(' ');
        if x == '?' && y == '?' {
            untracked += 1;
            continue;
        }
        if matches!(x, 'M' | 'A' | 'D' | 'R' | 'C') { staged += 1; }
        if matches!(y, 'M' | 'D') { unstaged += 1; }
    }
    (staged, unstaged, untracked)
}

fn build_status_parts(staged: usize, unstaged: usize, untracked: usize) -> Vec<String> {
    let mut parts = Vec::new();
    if staged > 0   { parts.push(Style::new().fg(Color::Green).paint(&format!("+{staged}"))); }
    if unstaged > 0 { parts.push(Style::new().fg(Color::Red).paint(&format!("!{unstaged}"))); }
    if untracked > 0 { parts.push(Style::new().fg(Color::Yellow).paint(&format!("?{untracked}"))); }
    parts
}
```

**設計上の判断**:

- リポジトリ判定は `read_file(.git/HEAD)` の成否のみで行う。リポ外なら exec を一切呼ばない。
- `git -C <repo_root>` は使わない。yosh の `commands:exec` は子プロセスにシェルの cwd を渡すため、引数なしでサブディレクトリからでも動作する。引数生成のエスケープ問題を回避できる。
- `.git` がファイル形式の worktree（`gitdir: <path>` で linked worktree を参照する形態）は **v0.2.0 では非対応**。`gitdir:` 解釈は将来追加可能。README の Limitations に明記。

## README の変更点

1. インストール例の version を `0.2.0` に更新。
2. Build from source セクションを wasm 用に書き換え (`cargo install cargo-component`、`cargo install wkg`、`rustup target add wasm32-wasip2`、`cargo component build --target wasm32-wasip2 --release`)。
3. Required Capabilities テーブルに `files:read` と `commands:exec` を追加。
4. **Configuration**（必須）節を新設し、`plugins.toml` に必要な設定例を載せる:

   ```toml
   [[plugin]]
   name = "rich-prompt-plugin"
   source = "github:k-ymmt/rich-prompt-plugin"
   version = "0.2.0"
   enabled = true
   allowed_commands = [
       "whoami",
       "hostname",
       "git status:*",
   ]
   ```

   - `commands:exec` capability は `allowed_commands` を設定しないと全コマンドが拒否される。
   - 設定漏れ時の縮退: user/host が `"user"` / `"host"` フォールバックに、git ブランチ名のみ表示（カウント省略）。
5. **Limitations** 節を新設:
   - `.git` がファイル形式の worktree（`git worktree` で作成された linked worktree）は v0.2.0 では非対応。
   - `git` / `whoami` / `hostname` コマンドが PATH にない環境では各機能が表示省略 / fallback 値になる。

## テスト戦略

旧 `git::render` の tempfile + git2 ベース統合テストは新環境では走らせられない（`read_file` / `exec` は yosh ランタイム上でのみ動作）。pure 関数として切り出した部分を単体テストでカバーする。

| ファイル | テスト方針 |
|---|---|
| `character.rs` | 既存 3 ケース全部維持（pure） |
| `directory.rs` | 既存 6 ケース全部維持（pure） |
| `duration.rs` | 既存 7 ケース全部維持（pure） |
| `username.rs` | `truncate_hostname` を `pub(crate)` として既存テスト維持（`on_load` から呼ぶため公開）、新 `render(user, host)` の固定入力テストを追加 |
| `git.rs` | **撤去**: 旧 7 件の tempfile ベーステスト。**追加**: `parse_branch` の単体テスト（normal branch / detached HEAD / 末尾改行 ±）と `parse_status_porcelain` の単体テスト（混在 / `??` / `MM` / 空入力 / 末尾改行） |
| `lib.rs` | 単体テストなし。手動スモークテストで担保 |

`find_head` および実際の `exec`/`read_file` 呼び出しはホスト依存のため単体テストせず、手動スモークテストでカバーする。

### 手動スモークテスト チェックリスト

1. ビルド成功: `cargo component build --target wasm32-wasip2 --release` が `target/wasm32-wasip2/release/*.wasm` を生成
2. インストール成功: `yosh plugin install <path>.wasm && yosh plugin sync`（`plugins.toml` に `allowed_commands` 設定済み）
3. yosh 起動時にクラッシュしない、プロンプトが表示される
4. 各 segment 表示確認:
   - **username**: `user@host` がシアン太字
   - **directory**: `~/...` 形式、ホーム外では絶対パス
   - **git (リポ内)**: マゼンタ太字ブランチ名 + Nerd Font icon + ステータスカウント
   - **git (リポ外)**: 表示されない
   - **duration**: `sleep 3` 直後に `took 3s` が黄色
   - **character**: 成功時 緑 `>`、失敗時 赤 `>`
5. 縮退動作:
   - `allowed_commands` から `git status:*` を除外: ブランチ名のみ表示、カウント省略
   - `commands:exec` capability を取り上げ: user/host が "user"/"host"、git カウントなし、ブランチ名のみ

## リスクと未確定事項

- **`Instant::now()` が wasm32-wasip2 + 空 WasiCtx で動作するか**: 動作する見込みだが、実装中に `wasi:clocks/monotonic-clock` 依存で失敗する可能性が残る。失敗時は `commands:exec date +%s%N` でフォールバック。
- **`yosh-plugin-sdk = "0.2"` の crates.io 公開状況**: 未公開なら git tag 指定に切替。
- **cargo-component 出力ファイル名**: 実ビルドで確認のうえ CI の rename 処理を確定。
- **worktree (`.git` ファイル形式) 非対応**: 既存ユーザーで影響を受ける場合は別 issue / 将来バージョンで対応。
